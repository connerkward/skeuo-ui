# Sprite-Isolation Recommendation — skeuo.fm spritesheet-pipeline

> Output of the `sprite-isolation-ideation` workflow (28 agents: map real code → 5 ideation lenses → judge each of 20 approaches → synthesize). Grounded in the real shipping code, not a proxy. 2026-06-23.

## ⚠️ Empirical correction (2026-06-23, verified on real mattes) — READ FIRST

The workflow's **#1 recommendation (chroma background) is NOT validated by real output** and is **deferred**, not adopted. I ran the actual shipping BiRefNet (`fal-ai/birefnet/v2` Heavy, via `/api/cutout`) on real strips from the three hardest skins — brushed-aluminum (`823d`), pearlescent Frutiger (`mnyh`), chrome-aqua (`7co6`) — on white bg vs a flood-fill chroma bg. Result: **the white-bg matte is already clean on all three, and the chroma version is pixel-identical.** White-on-white **did not manifest** — the model never paints controls pure-white even for silver/chrome/pearlescent prompts (it adds shading, reflections, dark icons → contrast). The chroma fix was reasoned from the *code* (`detectCellContent`'s `>234` test, the `wmp` "silver-white" material), not from looking at output. **Do not adopt chroma until a real skin is found where the white matte drops a control.** The one real defect seen was caught text labels — but those were *old pre-label-less strips*; the current blank-strip prompt already prevents that. (Demo page: `/tmp/iso-examples/`, mattes in `~/Desktop/cc-skeuo/fal-outputs/`.)

So the remaining live, *verified* problems are: **(a) the play-overlap repack bug** (§4 — reproduced on real templates), and **(b) the sprite↔socket shape/consistency gap** (controls cut from the strip are force-fit into device sockets — not a contrast problem). The isolation contrast plan below is kept for reference but is **lower priority than first proving a failure exists**.

## 0. Engine decision (locked): fal only, no local ComfyUI in the runtime

The cutout is **productionized to a server** (the Cloudflare Worker / `functions/api/cutout.ts`), which **cannot reach a localhost ComfyUI**. So BiRefNet runs on **fal** (`fal-ai/birefnet/v2`) for every runtime path — dev parity included. The workflow's "local ComfyUI / free on MPS" recommendation (#4) is **dropped** for the runtime; ComfyUI stays only as an offline authoring artifact, never a server workload. This re-weights cost: **every matte call is a paid fal call**, so the plan below minimizes call count — favor a prompt-only fix that keeps the single whole-strip matte over anything that multiplies matte calls per skin.

## 1. The crux

Isolation is hard because the shipping path does **one whole-strip BiRefNet matte at a fixed 2048² over N controls painted on pure white**, then leans on noisy downstream heuristics (`keepCenterComponent`, `cutLooksFailed`) to recover per-control sprites. That single design choice manufactures all five failure modes at once: small controls get a few pixels (erosion), abutting cells share a matte (neighbor bridging), white/silver/chrome controls have zero fg/bg contrast (white-on-white loss), and the only fallback (`cutSprite`) is itself white-blind. **The single highest-leverage move — and it costs zero extra fal — is to stop matting white-on-white: give the painter a non-white strip background by construction (prompt-only), so the existing single whole-strip matte gets real contrast.** Blanket per-cell matting also fixes neighbor/erosion but at N× fal cost, so it is demoted to a **bounded retry on QC-failed cells only**, not the default — everything else is free, deterministic polish.

## 3. Recommended plan (ordered, minimal, composes)

The goal is robustness **by construction**, biasing free/local/deterministic over noisy-model heuristics. Five changes, in order; each is independently shippable and each makes the next cheaper to verify.

**A. Generation-side — kill white-on-white at the source (#1).**
In `src/generate/pipeline.ts` `PAINT_PROMPT` (the strip clauses ~`:62-65` and `:75-78`), change the strip background from flat `#FFFFFF` to a **single flat saturated key chosen outside every entry in `MATERIAL`** (`blueprint.ts:85` — note the `frog` green material; do NOT use green, and keep clear of the socket keyline magenta `BP_RING`). Assert the rendered strip-bg is the key before proceeding. Prompt-only, zero fal cost, the one change that gives the matte real contrast on silver/chrome/flat-white.

**B. Crop/instance — crop each cell from raw paint, matte individually (#2).**
In `src/generate/cutoutClient.ts` `finishCutoutFull` (`:424-437`): replace the single `serverCutout(strip, "General Use (Heavy)")` at `:433` and the `cutFrom` rescale closure (`:425-428`) with a per-cell loop — for each layout cell, crop the `cellRect` sub-rect from the **raw paint**, then `serverCutout(cellCanvas, …)` per cell. This **deletes neighbor pixels before the matte ever sees them** and **voids the unverified fx/fy 2048² rescale assumption** (failure 5) because each matte's dims equal its input crop's dims. Parallelize with `Promise.all`. `keepCenterComponent` becomes a near no-op.

**C. Matting-support — route the matte to local, and add the missing edge cleanup (#4 + #6-half).**
- Wire the dev `/api/cutout` backend (`server/devApiPlugin.ts` `:94-113`) to the local ComfyUI BiRefNet behind a `LOCAL_MATTE` flag (default on in dev), **porting the existing `generation/comfyui/skeuo-pipeline.workflow.json`** rather than authoring new (discover-before-building); keep fal as the prod/CF fallback (the edge Worker can't reach localhost). First confirm the local node exposes a Heavy/Matting-equivalent path. Makes B's N calls **free** to iterate.
- In `cutFromTransparentStrip` (`cutoutClient.ts:185`, after `keepCenterComponent`, before the alpha-trim at `:204`): add a **1px alpha erode** (port the loop from `blueprint.ts:138-148` — the BiRefNet path currently has none) plus a **hue-distance JS clean** that zeros any residual key-color halo from A. Free, deterministic, fixes failure 3 on every skin.

**D. Validation — replace the white-blind gate with a geometric QC (#3).**
Rewrite `cutLooksFailed` (`cutoutClient.ts:331`) into `qcSprite(sprite, cellRect, kind)` returning `{ok, reason}`, **run BEFORE the bbox-trim**: (a) opaque-frac < ~0.06 → lost; (b) alpha-bbox ≥ ~0.95 of cell dim → bled to edge/neighbor; (c) per-kind aspect sanity (knob/button/toggle ≈ square); (d) 2nd-largest component > ~25% of kept → neighbor not dropped. Surface `reason` so failures route to retry, not silently to a donor. Score before the cosmetic trim (verify-outputs §6).

**E. Retry — bounded, QC-gated, only after the seam is fixed (#7).**
On `qcSprite` fail, re-cut that one cell at full res over a contrasting backing. **Precondition: fix `functions/api/cutout.ts` (`:47`) to parse and pass through `?model=`** (it currently ignores the query param, so the "Heavy" call and any "Matting" retry may be silent no-ops defaulting to Light in the deployed Worker — validate the model against a union). Cap at one escalation; route to local (C). If still failing, fall to the geometric cut — and accept it routes to a donor on the hardest skins (honest failure-surfacing, not a wrong sprite).

After each step, **verify in the REAL app** — `Recut.tsx` already runs `finishCutoutFull` on saved generations; open the individual full-res sprites for the **worst** chrome/radial/low-contrast skins, not a pass-count and not a `/tmp` Python proxy (verify-outputs §6/§7).

## 4. The repack play-button-overlap fix

The overlap is **not** an enlarge-after-resolve ordering bug — `repackTemplate` (`layouts.ts:422-435`) correctly enlarges play (`:426`, `cw*=1.25`) **before** `resolveOverlaps` (`:434`), and the Stage-2 diagram faithfully draws the saved template. The real cause: on dense AI-Director layouts, `resolveOverlaps` silently gives up and **shrinks the enlarged play below baseline** (reproduced on real artifacts: play driven from `w=0.1625` down to `0.1276`, *smaller* than a normal button). Three compounding mechanisms: the 60-iteration MOVE pass can't converge because `display`-kind controls are hard-fixed (`:338`) and box the transport row in; the 8-pass SHRINK loop hits the `0.07` floor against the full-width seek; and shrink target selection (`:381`) picks the smaller-area box, so sandwiched play becomes the victim and the `1.25` enlargement is undone. Robust fix is structural: **constrain Director regions into kind-appropriate zones first** (displays top, transport row below seek, EQ in its own band) so `resolveOverlaps` only polishes. Immediate guard: add a per-control `noShrink`/canon floor in `repackTemplate`, exclude enlarged/priority controls from being the shrink victim at `:381` (clamp `newW = Math.max(canonW, r.w - dropW)`), and **after the passes assert zero residual overlap and throw/log** so an unresolvable template never reaches the painter silently.
