# 2026-07-09 — Ambient video loops from finished gen12 paints (image-to-video)

## Question

Can an image-to-video model add **ambient life** (steam wisps, ember flicker, water droplets)
to a finished skin paint while keeping the **device perfectly static** — no control motion, no
camera motion, no silhouette change — suitable as a looping background layer behind the
runtime-controlled widgets?

## Method

- Subjects: device-area crop of `paint.png` (top 75%, `devFrac`) for 3 gen12 skins:
  `assets-steam-porthole`, `assets-diablo-gothic`, `assets-fa-sky`.
- 1 gen per skin per model, prompt pattern:
  *"static camera, the device stays perfectly still; subtle ambient motion only: [theme
  effects]; no user interaction, no buttons move, no parts move, seamless ambient loop"*.
- Models (fal.ai):
  - **Premium:** `luma/agent/ray/v3.2/image-to-video` — $0.50 per 5 s unit, 720p, native
    `loop=true` (the only catalog i2v model with a native seamless-loop flag). Input padded
    to 3:4. Output came back 8.75 s @ 24 fps.
  - **Cheap:** `fal-ai/wan/v2.2-a14b/image-to-video/turbo` — $0.10 per video, 720p tier,
    seed 1207. Rejects `aspect_ratio=auto` for this input shape (422: resolved 864×1040
    unsupported; only 16:9 / 9:16 / 1:1) → input padded to 1:1, output 960×960, 5 s @ 32 fps.
- Loop post (`ambientvid/postloop.sh`): Luma = native flag, straight re-encode; Wan = 1.0 s
  ffmpeg crossfade (tail xfaded over head, `trim`+`xfade`+`concat`), → mp4 (libx264 crf 16,
  yuv420p, faststart) + webm (vp9). Seam metric = mean |first−last frame| px diff.
- Verified per video-capture-rule: ffprobe all outputs + extracted 2–3 mid frames per gen and
  inspected at full res; loop seams measured numerically.
- Cost: 3×Luma ≈ $1.50–$3.00 (billed per 5 s unit; 8.75 s output makes rounding unclear) +
  3×Wan = $0.30. **Total ≈ $1.80–$3.30** (3 Wan validation rejects not billed). Budget was $6.

## Results (per-skin verdicts)

| skin | Luma Ray 3.2 (premium, native loop) | Wan 2.2 turbo (cheap, xfade loop) |
|---|---|---|
| steam-porthole | **FAIL** — replaced the entire device with a photoreal glass cylinder + brass base + real smoke within ~2 s. Full object substitution. Seam 15.8. | **PASS** — device static, all controls intact; gauge needles quiver, highlights breathe. Steam wisps under-generated (motion very subtle). Seam 2.2. |
| diablo-gothic | **PARTIAL** — device geometry preserved and the ember/rune flicker is the best of the batch, but a slow camera push-in the whole clip despite "static camera". Native loop doesn't close (seam 8.9). | **PASS** — best overall. Device perfectly static, rune/ember glow pulses on-theme, tightest seam of the batch (1.6). |
| fa-sky | **FAIL** — translucent body "breathes": silhouette inflates/deflates, chrome S-wave swims. Seam 6.1. | **FAIL** — silhouette holds and the internal waterline slosh + droplet glints are exactly the wanted effect, but by ~1.5 s the chrome trim (mid S-wave, bottom-left flap) dissolves into the aqua body permanently. First frame faithful, then trim melts. Seam 2.6. |

## Key findings

1. **The cheap model won.** Wan 2.2 turbo ($0.10) kept the device static on 2/3; Luma Ray 3.2
   (~10× the price) on 0/3 — it substituted an object, pushed the camera, or morphed the body.
2. **Luma's native `loop=true` under-delivers**: measured seams 6.1–15.8 px mean diff vs
   1.6–2.6 for a plain 1 s ffmpeg crossfade. The crossfade in post is both cheaper and cleaner.
3. **Failure mode is content drift, not control interaction**: no model pressed buttons or
   moved sliders; the "no user interaction" clause held. What breaks is object identity —
   substitution (Luma/steam), camera motion (Luma/diablo), material dissolution (both/fa-sky).
4. **Translucent/liquid materials are the hardest case** — chrome trim on a translucent body
   dissolved in both models; opaque stone (diablo) was the most stable.
5. Effects that worked: ember/rune glow flicker (both), gauge-needle quiver (Wan), internal
   waterline slosh + droplets (Wan). Effects that failed: steam wisps (under-generated by Wan,
   object-hallucinated by Luma), any chrome/silver trim on translucent bodies.
6. Wan turbo gotcha: `aspect_ratio: "auto"` 422s on non-standard input shapes on the
   distributed GPU endpoint — pad to 1:1/16:9/9:16 first.
