twoimg — separate the layout from the canvas (multi-image conditioning)

Hypothesis: guide-colour bleed happens because colour-coded guide shapes are physically painted INTO the edit-target canvas — sending the layout as a SECOND reference image with a guide-pixel-FREE clean target makes bleed impossible by construction (verified: the clean scaffold contains zero pixels within RGB-distance 60 of any guide key, checked programmatically before any generation ran).
Arms (both use SOLID FILLED guide shapes, the abshape-verdict 2026-07-09 winner): CONTROL = current single joint canvas (left=guided blueprint, right=black mask target), 1 input image. TREAT = image 1 (edit target) is a CLEAN scaffold with the SAME geometry and ZERO guide- coloured pixels; image 2 is the SAME guided blueprint as CONTROL, sent purely as a layout reference the prompt says is never painted.
Model: gemini-3-pro-image-preview via Vertex AI direct (project muser-2605300220, global), 4K, 5:4 — same underlying model the fal path proxies, chosen because it's the already-proven ~20%-cheaper path (gen12/TODO.md) and both fal's image_urls: array<string> schema AND Vertex's multi-inline_data-part generateContent shape confirmed multi-image support before this ran (see genskin_twoimg.py docstring).
Scoring: ../extract12.py pass 1 (no matte) for the shared gates (leak/emptiness/controls/ region-placement) PLUS a bespoke perimeter-band hue-distance bleed-ring metric (this script's own — the shared leak gate under-counts thin rings/bezels per the abshape verdict, so this experiment measures its actual target defect directly).
SOTA eye review (this agent is Sonnet, sub-SOTA — per sota-eye-review-rule the final visual call is routed through a SOTA vision model): 8 calls to google/gemini-2.5-pro via fal openrouter/router/vision, one per generation, each sent the downscaled full paint + full-res vol/seek/shuffle/playpause/queue crops with guide-colour NAMES stated, asked for a per-control residue call (NONE/RING/FLOODED) + emptiness + one VERDICT line.
Cost: 8 gens × ~$0.24/4K image ≈ $1.92 generation + 8 VLM calls × ~$0.02 ≈ $0.16 review ≈ $2.08 total (extraction/scoring local, $0).
Verdict:
HYPOTHESIS FALSIFIED — two-image conditioning does NOT eliminate guide-colour bleed, and it costs layout adherence.

Bleed axis (the thing the treatment was supposed to make impossible): guide-hue residue appears in BOTH arms at similar-or-worse rates in TREAT. Hand-verified at full res + SOTA-eye (gemini-2.5-pro) per-control calls: CONTROL shows guide-hue echo in 2/4 gens (fa-pod-134: button ICONS painted in their exact guide hues — red play, magenta next, orange repeat, yellow queue; wc-goldshield-134: prev/next/repeat/queue button gems FLOODED green/pink/green/red = their keys). TREAT shows residue in 3/4 gens (fa-pod-134: VIOLET-PURPLE ring around the vol socket + the seek groove FLOODED deep-purple — vol/seek's exact guide keys, transferred from image 2 even though the edit canvas contained ZERO guide pixels (verified programmatically pre-run); wc-treat-121: shuffle RING). The bleed pathway is SEMANTIC — the model reads the reference image's colours and paints them as design elements — not just pixel-tracing of the canvas, so removing guide pixels from the canvas does not remove the defect.

Layout-adherence cost (clear and consistent): CONTROL follows the locked template closely in 4/4 (rows/positions as authored). TREAT drifts in 4/4 — fa-pod-treat-121 collapses the 5-button row into a 2x2 cluster and moves the shuffle slot; wc-treat-121 and wc-treat-134 fully rearrange (screens moved to bottom / playpause pulled out of the row); fa-pod-treat-134 fails the region-misplaced gate (visualizer). TREAT also baked MORE parts into must-be-empty cavities (VLM cavity calls: FILLED on vol/seek/shuffle in all 4 treat gens vs 1/4 control — e.g. a thumb baked into fa-pod-treat-121's seek groove; note the deterministic bright-interior gate passed these because mid-tone/dark fills sit under its >150 brightness threshold, so the VLM caught a real gap in the automated gate) and introduced text labels (OFF/ON on fa-pod-treat-121's strip switches) — both explicit prompt violations.

Metric caveat recorded for honesty: the bespoke perimeter-band hue metric false-positives on wc-goldshield's queue in BOTH arms (8-39%) because the gold body hue (~42deg) sits inside the 16-step hue tolerance of the YELLOW guide key (~60deg) — those numbers measure the body material, not residue; same-theme cross-arm deltas are still usable, absolute values are not.

Recommendation: KEEP the single-canvas solid-guide blueprint (abshape verdict stands). Do not adopt multi-image conditioning for layout. If bleed reduction is pursued further, the lever is prompt/colour-selection (e.g. avoid keys hue-adjacent to the theme palette, strengthen the no-echo clause for ICONS specifically — icon fills were the most common echo site) rather than conditioning topology. n=4/arm: directional, not conclusive.
