User overrule of the prior pass (commits 8a7e081f / e242a2eb): "knob-zero fix is fail. did you even cross check with vlm? these lines are off. near, but off and noticeably." The prior verification was VLM-witnessed PASS — a VLM cannot judge small angular error (it's a witness, not a judge) — and the old proof page's annotation arrows were drawn by annotate.py, which reimplemented the centroid/radius geometry independently of the real detector instead of reading its stored output (a verify-outputs-rule §7 proxy-trap). This page replaces both: real pixel measurement instead of a VLM witness, and annotations drawn from stored detector values instead of a reimplementation.

Root cause(s), investigated in suspicion order

  • CONFIRMED — (a) bin-quantization bias, the actual bug. The old detector returned the winning angular bin's leading edge (peak * bw, nbins=180 → bw=2°) with zero sub-bin refinement. Proof: every stored knob_zero_deg pre-fix was an exact multiple of 2° (84.0, 142.0, 94.0, 354.0, 4.0, 0.0 — never a fractional degree, across 6 independent paints). Re-running the identical algorithm with 3-point parabolic sub-bin refinement on the same raw sprites shifted every value by +1.0° to +1.9°, a small but real, systematic, fully generalizable bias affecting every knob in the pipeline, not a per-skin fluke. This is the fix shipped in knob_angle.py (shared by extract12.py, no duplicated math).
  • RULED OUT — (b) rotation-center error. Measured directly: the raw sprite's alpha centroid (old detector's origin) vs. its alpha bounding-box center (what build_player.py's tight()+background-size:cover actually renders around) differ by <1.5px / <0.3° on all 6 sprites — negligible. The detector now centers on the bbox center anyway (matches the render exactly), but this was never the dominant error.
  • RULED OUT — (c) CSS transform-origin / aspect mismatch. build_player.py sets --ar: PW/DEVH on #phone, which makes any seat-radius-derived box render as a true geometric square in pixels regardless of paint aspect ratio or devFrac — verified algebraically and by the closed loop itself (a transform-origin bug would show up as a LARGE, direction-dependent render error; none was found). .pknob .cap's default 50%/50% origin correctly coincides with that square's center.
  • CONFIRMED (on principle) — (d) proof-page proxy trap. The old knobzero-proof/annotate.py reimplemented the centroid/radius math instead of reading extract12.py's stored output — it happened to land on near-identical numbers here (same reason (b) was ruled out: centroid≈bbox-center for these mostly-circular cutouts), so it wasn't the source of the angular bug, but it was still the wrong practice and is fixed regardless: regions.json now stores knob_zero_geo (the detector's own measured center+radius) alongside knob_zero_deg, and the raw-sprite overlays below are drawn from those stored values by annotate2.py, never re-derived.

Verifier calibration note (affects measurement only, not the pipeline fix): the render-domain scan uses r_hi=0.80 (vs. the sprite-domain 0.94) to stay inside the cap's own opaque knurled rim and avoid the soft alpha-blend zone where border-radius:50% clips into the phone's body art — verified directly (fallout-vault read a spurious 20.8° error at r_hi=0.94 from that contamination; 0.80 recovered 0.9°, corroborated by an independent manual pixel-centroid check and a full-resolution visual crop). z_thresh=4.5 (vs. sprite-domain 5.0) accounts for CSS-rotation raster blur attenuating peak sharpness; every skin but ps1-crunchy (smallest crop, thinnest pointer, z=4.6) clears 8.3–245.8, so the looser gate carries no false-positive risk in this batch — doubling capture resolution made ps1-crunchy's signal WORSE, confirming a raster-blur floor rather than a resolution shortfall.

Conclusion

The user's qualitative call was correct — the prior VLM-witnessed pass was insufficient to catch a real, systematic angular bias, and the reimplemented proof-page annotations were the wrong verification method on principle. The quantitative magnitude was smaller than the "5–20°" working hypothesis: the actual bug (bin-edge quantization with no sub-bin refinement) was worth +1.0° to +1.9° per skin, and the closed-loop render measurement (a different, independent check from the extraction-time detector — real DOM layout, real CSS transform, real browser rasterization, none of which the extraction step touches) found pre-fix render errors of 0.56°–3.72° against a 12-o'clock target, not double digits.

Post-fix, every knob in the batch measures ≤2.32° render error, clearing the ≤3° acceptance bar:

  • steam-porthole 2.83° → 0.44°
  • ps1-crunchy 1.21° → 0.69° (weakest signal in the batch — smallest crop, thinnest carved pointer — but consistently detected and consistently near-zero across both passes)
  • myst-arcanum 0.56° → 0.89° (both readings are noise-level; ambiguity between the two carved marks is a source-art call, unaffected by this fix — see note below)
  • fallout-vault 0.88° → 0.98° (noise-level both ways)
  • fa-pod 1.02° → 1.29° (regression control, noise-level both ways, still exact-match visually)
  • n64-cutscene 3.72° → 2.32° (only skin over the 3° bar pre-fix; now under it)

The fix is generalizable (shared knob_angle.py module, not a per-skin patch) and the verification is real (measures the actual shipped player.html render, not a reimplementation of the geometry). myst-arcanum's two-mark ambiguity is unchanged and still pending a human call — see the note below; it is a source-art question, not a detector bug, and this fix does not resolve it either way.

myst-arcanum — pending human call (unchanged by this fix): this cap carries two carved marks — a V-notch near 0° and a thin wedge slit near 94–95°. The detector's relative-signal metric picks the wedge as the stronger local radial anomaly; a VLM cross-check independently argued the V-notch (design convention: indicators default to 12 o'clock) is more likely "intended." Neither geometric feature disambiguates — this remains a genuine ambiguity in the source art the wedge choice stands until the user rules otherwise.
