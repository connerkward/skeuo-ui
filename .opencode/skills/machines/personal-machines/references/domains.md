## Redirect mechanism (Cloudflare)

301s are done as per-zone **Single Redirects** via API:
`PUT /zones/{id}/rulesets/phases/http_request_dynamic_redirect/entrypoint` with a rule
`expression:"true"`, action `redirect`, `target_url` =
`concat("https://connerkward.dev", http.request.uri.path)`, status 301,
`preserve_query_string:true`. The source zone needs a **proxied** DNS record for the
edge to intercept (all three already had proxied records, so no placeholder needed).
An HTTP redirect does **not** touch DNS or email records (MX/SPF/DMARC/DKIM stay live),
and is reversible (delete the ruleset rule).

## Cloudflare API token

`CLOUDFLARE_API_TOKEN` in `central/.env` (what the `cloudflare` skill reads). The
original `Account Settings: Edit` token was **rolled** (and thus invalidated) while
creating a replacement; the current token is scoped **`Zone:DNS:Edit` +
`Zone:Single Redirect:Edit` + `Zone:Zone:Read`** (verified working for the redirects).
**Gotcha:** this account's CF token secrets are **53 chars**, not 40 — don't assume
40. The correct permission name for redirect rules is **`Single Redirect`** (Edit), not
"Dynamic Redirect". If you need the skill's old RUM/analytics work, add
`Account Settings:Edit` back. See the `cloudflare` skill.
